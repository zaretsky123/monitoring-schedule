# График мониторинга

Интерактивный прототип для планирования круглосуточных 12-часовых смен и подбора замен с проверкой обязательных ограничений.

## Локальный запуск

```bash
pnpm install
pnpm dev
```

## GitHub Pages

Публикация выполняется автоматически после каждого push в ветку `main` с помощью workflow `.github/workflows/deploy-pages.yml`.

## Supabase

Переход на Supabase выполняется поэтапно. Пока переменные окружения не заданы, опубликованный прототип продолжает использовать браузерное `localStorage` и работает как раньше.

Первая миграция находится в `supabase/migrations/202609300001_initial_schedule_schema.sql`. Она создаёт:

- рабочее пространство руководителя;
- постоянный справочник сотрудников;
- месяцы и смены;
- несколько назначений сотрудников на одну смену;
- периоды недоступности;
- исходные и текущие назначения;
- пакеты изменений и их состав;
- RLS-политики, запрещающие анонимный доступ к рабочим данным.

Для локального подключения:

```bash
cp .env.example .env.local
```

Затем заполните `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY` значениями из Supabase. В клиентский код нельзя добавлять secret/service_role key.

GitHub Pages получает URL проекта и publishable key из workflow. Оба значения публичны в клиентской сборке; при смене проекта или ротации ключа обновите их в `.github/workflows/deploy-pages.yml`.

Publishable key попадает в статическую сборку, что является штатным режимом Supabase. Защиту реальных ФИО и графиков обеспечивают включённые RLS-политики и обязательная авторизация пользователя. Старый `NEXT_PUBLIC_SUPABASE_ANON_KEY` временно принимается для совместимости.

### Сохранение действующего редактора

В проекте Supabase уже применены три миграции: исходная схема, версионируемые снимки и ограничение рабочих пространств единственным администратором. Сохранение атомарно: если тот же график изменили в другой вкладке, текущая вкладка не перезаписывает чужую версию и оставляет правки в локальном браузере.

В Supabase Auth настройте URL сайта `https://zaretsky123.github.io/monitoring-schedule/` как разрешённый Redirect URL для входа по электронной почте. Не отключайте RLS и не публикуйте ключ `service_role`.

Сайт закрыт до входа. Вход `admin` + пароль проходит через Edge Function `admin-login`: она на сервере находит почту единственного администратора и проверяет пароль через Supabase Auth. Почта и секретный ключ в браузер не передаются. Первый вход выполняется по ссылке из письма для уже существующего пользователя; она не создаёт новые аккаунты. Затем в панели «Подключить» задайте собственный пароль длиной от 12 символов. Пароль не сохраняется в репозитории. В настройках Supabase Auth отключите создание новых пользователей (Allow new users to sign up), чтобы новые аккаунты не появлялись даже вне сайта. Независимо от этого база разрешает рабочее пространство только действующему администратору.

После входа выберите «Перенести мои графики», если нужны локальные данные браузера и облако пустое. Если снимок уже существует, сайт предложит открыть его, предварительно сохранив локальную копию в браузере. Дальше изменения сохраняются автоматически, а локальная копия продолжает обновляться.

### Сотрудники

Раздел «Сотрудники» содержит общий справочник с постоянными ID, ФИО, периодом работы, статусом и флагом «Тестовый». Сотрудников добавляет администратор вручную. Добавление в справочник не назначает смены; состав текущего или нового месяца выбирается отдельно, до 8 участников. Сотрудника можно включить и в уже закреплённый график, пока месяц не завершён.

Редактор, поиск замен, генератор, показатели и Excel используют постоянные ID. Одинаковые ФИО и переименование не объединяют назначения. Дата начала ограничивает начало смены; дата увольнения ограничивает её окончание, включая ночные смены. Архивирование скрывает сотрудника из новых составов, сохраняя графики и историю; период работы задаётся отдельно.

Тестовые сотрудники имеют тот же функционал. График с тестовым участником получает постоянную пометку «Тестовый», которая сохраняется и после закрепления или удаления тестового сотрудника. Контекст соседних тестовых и рабочих месяцев не смешивается. Удаление тестового сотрудника очищает его назначения и ссылки в тестовых графиках; освободившиеся смены нужно заполнить заново. Тип сотрудника фиксируется при первом включении в график.

Справочник хранится в поле `employees` существующего атомарного снимка `schedule_snapshots.payload` вместе с месяцами и историей. Старые снимки без этого поля продолжают поддерживаться с прежними четырьмя записями; новый тестовый справочник автоматически не создаётся. Нормализованные таблицы сотрудников и назначений пока не используются: приложение не выполняет двойную запись. На одной дневной или ночной смене поддерживаются два отдельных назначения.

Проверки: `pnpm test:algorithm`, `pnpm test:coefficients`, `pnpm test:employees`, `pnpm build:pages`.

### Защита сохранений и восстановление

`schedule_snapshot_versions` хранит полные серверные версии без автоматического удаления. Триггер в закрытой схеме сохраняет старую и новую версии в той же транзакции, что и запись `schedule_snapshots`: ошибка создания копии откатывает запись. История доступна владельцу только на чтение; приложение не может менять или удалять её. Копии не удаляются каскадно вместе с рабочим пространством. `restore_schedule_snapshot` создаёт новую версию через прежнюю проверку ожидаемой ревизии, сохраняя заменяемую запись.

В интерфейсе видны состояние сохранения и остановка синхронизации. Копию текущей вкладки со всеми сотрудниками, месяцами и черновиками можно скачать независимо от состояния облака. Перед открытием отличающейся облачной версии, восстановлением, очисткой месяца или удалением черновика/тестового сотрудника создаётся отдельная локальная копия. Старые локальные копии не удаляются автоматически; повреждение или переполнение хранилища останавливает действие. Экспорт включает эти копии в `_recoveryCopies`. Перед закрытием вкладки с неподтверждёнными облачными изменениями браузер показывает предупреждение.

Последняя успешно сохранённая/загруженная облачная копия хранится отдельно от рабочего состояния. При входе неизменённый кэш может автоматически обновиться из БД, а отличающиеся несохранённые локальные данные требуют явного выбора и сначала резервируются. Сравнение не зависит от порядка полей JSON. Очередь сохранений привязана к сеансу синхронизации, чтобы отложенные старые задания не продолжались после переключения версии или выхода.

В «Сохранении и восстановлении» доступны последние 30 серверных версий (ограничение списка, не срока хранения): скачивание и восстановление с подтверждением. Восстановление запрещено при неподтверждённых локальных изменениях; конфликт ревизии не перезаписывает актуальные данные. Проверки: `pnpm test:recovery`, `scripts/test-snapshot-history.sql` (отдельные временные тестовые записи и `ROLLBACK`), сборка Pages и функциональная проверка интерфейса. Внешние резервные копии также необходимы: история в одной БД не заменяет независимый экспорт.

В меню выбранного месяца есть «Очистить месяц» с подтверждением. Текущий или будущий график возвращается в ручной черновик: назначения, замочки, усиления, исходный план и история изменений удаляются. Состав сотрудников и все периоды недоступности сохраняются; недоступность из истории переносится в черновик. Переходящая ночь из предыдущего месяца сохраняет обоих сотрудников. Другие месяцы не очищаются. Завершённые месяцы защищены, включая повторную проверку при подтверждении.


### Карточка сотрудника и недоступность

Нажатие на ФИО в разделе «Сотрудники» открывает карточку с разделами «Обзор» и «Месяцы». Обзор показывает текущий календарный месяц по Москве, независимо от выбранного основного графика. Месяцы содержат сохранённые графики участия, итоговые назначения, показатели и периоды недоступности. При открытии месяца используется существующий фильтр «Показан … / Сбросить». Переключение месяцев сохраняет снятый фильтр.

Завершённые месяцы доступны только для просмотра: красные маркеры открывают подробности изменений, откат и изменение назначений запрещены. Открытие истории не перезаписывает завершённый снимок и не синхронизирует его входящую ночную смену заново. В графике фамилия обрезается многоточием по доступной ширине, инициалы остаются видимыми; полного ФИО в подсказке при наведении нет.

В черновике период недоступности сохраняется отдельно: целые дни включают последнюю указанную дату, точное время задаёт границы интервала. При закрытии незаполненного сохранением периода предлагается сохранить его или продолжить ввод. Недоступные смены отмечаются серой штриховкой и крестом, назначения запрещены. Правый клик позволяет отметить или снять недоступность отдельной смены; для занятой смены черновика требуется подтверждение снятия назначения. В закреплённом графике занятая смена перераспределяется через расчёт вариантов. Левая кнопка сохраняет быстрое назначение свободной смены и меню занятой.

Необязательная ставка оплаты задаётся в ₽/час и фиксируется в месяце при закреплении плана. Для старых месяцев без сохранённой ставки отображается «Не задана». Даты создания и причины новых периодов сохраняются с графиком; у прежних применённых изменений дата берётся из времени применения изменения. Формат снимка — версия 8, чтение прежних версий сохранено.


### Усиление смен

После первого ручного назначения у остальных доступных сотрудников остаются приглушённые плюсики для добавления второго. Максимум — два разных человека на одной смене; снятие и замена работают отдельно для каждого. Вторые назначения учитываются в отдыхе, недоступности, статистике, коэффициентах и Excel. Обе половины усиленной ночной смены переходят между датами, а при создании следующего месяца наследуются оба сотрудника.

В окне автоматического заполнения есть необязательная кнопка «Усиление смен». Она временно возвращает график в режим выбора дневных и ночных смен в заголовке. Сверху расположены «Готово» и «Отмена»: готово сохраняет выбор и возвращает окно расчёта со списком дат и типов смен, отмена возвращает прежний выбор. Нажатие «Рассчитать варианты» запускает расчёт напрямую. Без выбранного усиления требуется один сотрудник, на отмеченных сменах — два. Незаполненное второе место не позволяет закрепить план. Ручные назначения и замочки сохраняются при расчёте. Для снятия усиления с занятого второго места сначала нужно снять его назначение. Выбор хранится в снимке месяца как отдельное второе место смены (`slot: 2`) с постоянным ID.
